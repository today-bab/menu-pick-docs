# 화면 리디자인 (Figma 시안) 설계

- 작성일: 2026-11-01
- 대상: menu-pick-frontend ("오늘 뭐 먹지", https://menu.todaybab.com/)
- 결과물: Figma 파일 `todaybab 디자인` (https://www.figma.com/design/LQF0ULuZ1qdHVaVmC27u5J) 안의 화면 시안과 컴포넌트
- 이 문서의 범위는 **디자인**이다. 코드 반영은 시안이 확정된 뒤 별도 작업으로 한다.

## 왜 하는가

지금 화면은 한 줄(세로)로 블록을 쌓는 구조다: 제목 → 지도 → 결과(메뉴·가게 목록) → 이전/다음 → 제외 필터 → 하단 고정 뽑기 버튼.
기능이 늘 때마다 블록이 아래로 하나씩 붙어서 **화면이 위아래로만 길어지고**, 무엇이 주인공인지 흐려졌다.
스타일도 Tailwind 기본값(주황 + 회색)이라 디자인을 따로 잡은 적이 없다.

## 목표

- 결과가 나왔을 때 **스크롤 없이** 보여야 하는 것: 뽑기 버튼, 뽑힌 메뉴와 가게들 (사용자가 정한 우선순위)
- **지도는 항상 보인다** (사용자 요구)
- 앞으로 기능이 늘어도 아래로 쌓이지 않고, 지도 위 떠 있는 버튼이나 시트로 들어갈 자리가 있는 구조
- 주로 **휴대폰 브라우저**에서 쓰는 **웹**이다 (앱 아님). PC 브라우저도 깨지지 않게 대응한다

## 하지 않는 것

- 다크 모드 시안 (현재 코드는 지원하지만 이번 시안에서는 라이트만)
- 기능 변경. 뽑기·제외·기록 동작 규칙은 지금 코드와 같다 (아래 "기록"의 화면 변경은 예외)
- 기록을 새로고침 후에도 남기는 것. **새로고침하면 기록이 사라지는 지금 동작을 유지한다** (사용자 결정)

## 실패로 보는 것

- 여전히 결과를 보려면 스크롤해야 하는 화면
- 네이티브 앱 흉내(앱 전용 제스처에 의존)라서 모바일 브라우저에서 어색한 화면
- 주황이 여기저기 칠해져 정돈된 느낌이 사라지는 것

## 결정된 것

### 구조: 지도 전체 + 바텀시트 (사용자 선택, 시안 A)

- 카카오 지도가 화면 전체에 깔린다.
- 지도 위 왼쪽 위: 서비스 이름 "오늘 뭐 먹지" (작은 떠 있는 라벨)
- 지도 위 오른쪽 위: 떠 있는 버튼 두 개 — **기록 N**, **제외 N**
  - N은 각각 이번 방문에서 뽑은 횟수, 제외 중인 개수. 0이면 숫자를 숨긴다.
- 화면 아래: 바텀시트. 뽑기 버튼은 시트 맨 아래에 항상 붙어 있다.
- 시트 높이 단계
  - 접힘: 안내 한 줄 + 뽑기 버튼 (뽑기 전)
  - 기본: "오늘의 메뉴" 라벨, 메뉴 이름(크게), 가까운 가게 2곳, "가게 N곳 더 보기", 뽑기 버튼 (결과가 나오면 이 높이)
  - 펼침: 가게 목록 전체 + 뽑기 버튼
- 가게 줄: 가게 이름, 거리, 카카오맵 링크. 선택된 가게는 주황. 가게를 누르면 지도 핀이 강조되고, 핀을 누르면 목록에서 선택된다 (지금 코드와 같은 동작).
- 펼침 높이: 화면 위쪽 약 30%는 지도로 남겨 선택된 핀이 보이게 하고, 가게 목록은 시트 안에서 스크롤한다 (내 판단).
- 제외 시트·기록 시트는 메인 시트 **위를 덮는** 별도 시트다 (닫기 버튼, 뒤 배경 살짝 어둡게). 열려 있는 동안 뽑기 버튼은 가려진다. 닫으면 메인 시트로 돌아온다. PC에서는 왼쪽 패널 내용이 바뀌는 방식 (내 판단).

### 위치를 모를 때 (사용자 결정)

- 위치 권한 거부·위치 조회 실패·미지원이어도 지도를 그린다. **정해 둔 기본 위치**를 중심으로 보여주고, 내 위치 점은 없다.
- 기본 위치는 서울시청 근처로 둔다 (내 판단, 바꾸기 쉬움).
- 뽑기는 지금처럼 실제 위치가 있어야 한다. 시트의 메뉴 자리에 위치 안내 문구를 보여준다.

### 웹이라서 정한 것

- 기준 폭 390px (모바일 브라우저). 주소창·하단 툴바가 가린다고 보고 하단 여백(safe area)을 둔다.
- 시트를 손으로 끄는 동작은 지도 이동·당겨서 새로고침과 부딪히기 쉬워서 **보조**로만 둔다. 펼치기는 "가게 N곳 더 보기"를 **눌러서** 하는 것이 기본이다.
- PC(데스크톱) 화면은 하나만: 지도 전체 + 왼쪽 고정 패널(시트 내용이 패널로 들어감).

### 기록 (사용자 요청으로 바뀌는 부분)

- 메뉴 이름 옆의 `‹ 이전 / 다음 ›` 화살표는 **없앤다**. 대신 지도 위 **기록 N** 버튼 하나로 합친다 (사용자 결정).
- 기록 버튼을 누르면 기록 시트가 열린다: 최신순, 한 줄에 "메뉴 이름 · 가게 N곳", 지금 보고 있는 결과는 주황 표시.
- 줄을 누르면 그 결과로 돌아간다 (메인 시트·지도가 바뀌고 기록 시트는 닫힘).
- 저장은 지금처럼 메모리, 최근 20개, 새로고침하면 사라짐.
- 참고: 지금 코드는 "이전 결과를 보다가 새로 뽑으면 그 뒤 결과를 버린다". 목록으로 바꾸면 이 규칙이 어색해질 수 있다 — 코드 작업 때 다시 정한다. 시안에는 영향 없음.

### 스타일: 깔끔·미니멀 (사용자 선택, 시안 1)

- 흰 바탕, 회색 단계로 위계. 토스 같은 정돈된 느낌.
- **주황은 메인 색이지만 아껴 쓴다**: 뽑기 버튼, 선택된 가게, 지도의 선택 핀, 떠 있는 버튼의 숫자에만.
- 메뉴 이름만 크고 굵게 (28px 안팎, bold), 나머지는 작고 차분하게.

## 그릴 화면 (모바일 390px, PC 1개)

1. 첫 화면 (뽑기 전): 지도에 내 위치, 시트 접힘 — 안내 한 줄(예: "근처 1km 안에서 골라 드려요") + "메뉴 뽑기"
2. 로딩: "위치 찾는 중…", "고르는 중…". 처음 뽑을 때는 접힌 시트에서 버튼만 바뀌고, 결과가 있는 상태에서 다시 뽑을 때는 이전 결과를 흐리게 남기고 버튼만 바뀐다 (내 판단)
3. 결과 — 기본 높이
4. 결과 — 펼침 (가게 목록 전체)
5. 제외 설정 시트: 대분류별 "○○ 전체" 칩 + 메뉴 칩. 대분류 통째 제외, 메뉴 하나 제외, 통째 뺀 대분류 안에서 메뉴만 다시 넣기. 빠진 칩은 흐리게 + 취소선 (지금 규칙과 같음)
6. 오류: 위치 권한 없음, 근처에 가게 없음, 제외해서 고를 메뉴 없음, 서버 오류. 
   - 결과가 없을 때: 메뉴 이름 자리에 안내 문구 (위치 오류는 기본 위치 지도 위에서)
   - 결과를 보던 중 다시 뽑다 실패: 보던 결과는 그대로 두고(지금 코드와 같음), 뽑기 버튼 바로 위에 얇은 안내 줄 (내 판단)
7. 기록 시트
8. PC: 지도 + 왼쪽 패널 (결과 기본 상태)

오류 문구는 지금 코드(`src/App.tsx`의 `locationNotices`, `errorNotices`)를 그대로 쓴다.

## 컴포넌트

반복 요소는 Figma 컴포넌트로 만든다. 나중에 코드 컴포넌트와 짝지을 수 있게 한다.

- 뽑기 버튼 (기본 / 비활성·로딩)
- 떠 있는 지도 버튼 (숫자 있음 / 없음)
- 바텀시트 틀 (손잡이 + 내용 영역)
- 가게 줄 (기본 / 선택)
- 메뉴 칩 (포함 / 제외), 대분류 칩 (포함 / 제외)
- 기록 줄 (기본 / 지금 보는 중)
- 지도 핀 (선택 / 기본), 내 위치 점

## 만드는 사람에게 맡기는 것

- 정확한 색 값(주황 계열, 회색 단계), 간격·모서리 값. 참고로 시안에서는 주황 `#FF6B00`, 버튼 모서리 14px, 시트 모서리 20px 정도를 썼다 (내 판단, 사용자 미확인)
- 글꼴: Pretendard 권장 (내 판단)
- Figma 변수(색·간격 토큰) 정리 방식
- 지도 영역은 실제 지도 대신 단순화한 이미지/도형으로 표현해도 된다
- 시트를 끄는 모양(손잡이) 표현 방식
